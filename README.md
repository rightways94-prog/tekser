# Тексер — ИИ-проверка БЖБ/ТЖБ по дескрипторам

Цепочка: фото работы → ИИ оценивает каждый дескриптор и пишет подсказку по первой ошибке → учитель правит и утверждает → карта ошибок класса, «что разобрать на уроке», баллы в CSV.

## Запуск
1. Node.js 20+ (nodejs.org).
2. В папке проекта: `npm install`
3. Скопировать `.env.example` в `.env`, вписать `OPENAI_API_KEY`.
4. `npm start` → http://localhost:3000

Без ключа работает демо-режим: работы А/Б/В и демо-класс; загрузка своих фото отключена.

## Устройство

### Пачка работ класса

На рабочем столе нажмите «📚 Проверить пачку работ» и выберите фото класса с напечатанными условиями. До запуска проверьте порядок страниц и распределение: по умолчанию по 2 страницы на ученика, можно выбрать 1–4 или изменить номер ученика у отдельного фото. До 30 работ (120 фото) в одной пачке; имена не нужны, используются коды У-01 и далее. При необходимости добавьте текст критериев/ключа учителя.

Для каждой работы отдельно распознаётся её условие и предлагается эталон, затем проверяется решение — разные варианты не используют ключ первой работы. Это два запроса ИИ на работу. Подготовка не принимает рукописный ответ ученика за эталон. Проверка последовательная, с прогрессом; остановка завершает текущую работу, после чего можно продолжить. Ошибки не превращаются в нулевые оценки: успешные результаты остаются в отчёте, у неудачной работы можно заменить 1–4 фото и повторить только её проверку.

Отчёт показывает балл/максимум, процент, замечания и подсказку; условие, эталон и дескрипторы ИИ можно раскрыть. Кнопка результата открывает прежнюю карточку проверки для правок и утверждения учителем. Стрелки позволяют просмотреть все страницы работы; «Открыть фото» показывает выбранную страницу крупно. Разные варианты получают отдельные локальные задания, поэтому их карты и счётчики не смешиваются. В отчёте есть общий счётчик согласия для утверждённых работ и выгрузка CSV (до и после правок). Фото, очередь и текущий отчёт живут только на открытой странице: перед закрытием выгрузите CSV. Утверждённые работы сохраняются обычным способом в браузере.

Маршрут `POST /api/batch-check {images, rubricText, lang}` обрабатывает одну работу из 1–4 сжатых фото и возвращает `{task, result}`. Для пачки действует отдельный лимит `BATCH_LIMIT_PER_HOUR` — по умолчанию 30 работ в час с IP, включая неудачные попытки. Старый `LIMIT_PER_HOUR` для одиночной проверки и подготовки задания не меняется. Нужен API-ключ; фото на сервере не сохраняются. ИИ может ошибиться при распознавании условия и построении эталона — проверьте оба перед утверждением оценки.

### Своё задание: «Любой СОР/БЖБ»

На рабочем столе откройте «Любой СОР/БЖБ», введите название, условие, эталон и дескрипторы — по одному на строку, каждый на 1 балл (до 30). Сохраните задание, загрузите 1–4 фото работы и утвердите результат. Для следующих учеников выбирайте это задание в списке. Проверка фото требует API-ключа; без ключа можно подготовить задание и пройти встроенное демо.

Вместо ручного ввода можно загрузить 1–4 фото листа заданий, необязательно добавить до 4 фото и/или текст критериев и ключа, затем нажать «✨ Подготовить с ИИ». Условие можно также ввести текстом в поле ниже. Фотографии сжимаются перед отправкой. ИИ переписывает переданные критерии/ключ, а недостающие ответы и дескрипторы предлагает самостоятельно. Поля заполняются с пометкой «Предложено ИИ — проверьте перед использованием»: отредактируйте их и сохраните обычной кнопкой. Автоматического сохранения нет. Для этой подготовки нужен API-ключ; она использует ту же модель и общий лимит, что и проверка работ. Фото на сервере не сохраняются.

Свои задания и утверждённые результаты хранятся только в текущем браузере. При недоступном хранилище задание доступно до перезагрузки, о чём появляется сообщение. Карта ошибок и счётчик доверия ведутся отдельно для каждого задания; ошибки своего задания соответствуют незачтённым дескрипторам. `data/tasks.json` менять не нужно, фото на сервере не сохраняются.

Серверные тесты без обращений к OpenAI: `npm test`.

Браузерные проверки пачки (нужны запущенный `npm start`, Python Playwright и `/usr/bin/chromium`): `python test/batch-browser.py` и `python test/batch-edge-browser.py`. Они используют тестовые фото, перехватывают ответы ИИ и не обращаются в OpenAI. Проверяют РУС/ҚАЗ, 375 px, 10 фото → 5 работ, остановку/продолжение, ошибки и повтор, CSV, правки/утверждение и изоляцию статистики.
- `server.js` — Express; `/api/check` отправляет фото в OpenAI (structured output по дескрипторам). Фото не сохраняются. Лимит своих фото — 5 в час с адреса.
- `public/index.html` — страница учителя (РУС/ҚАЗ), без сборки.
- `data/tasks.json` — задания, эталоны, дескрипторы, коды ошибок с советами к уроку. `data/demo.json` — вымышленные работы и класс.
- `AGENTS.md` — правила для Codex; `docs/codex-tasks.md` — задания для Codex.

## Данные
Только вымышленные или обезличенные работы; ученики — коды У-01, У-02…; ключ — только в `.env` на сервере.
